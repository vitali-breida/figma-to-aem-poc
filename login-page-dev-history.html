public interface PageNavigator {
    List<NavItem> getNavItems();
    boolean isEmpty();

    interface NavItem {
        String getTitle();
        String getHref();
        boolean isActive();
    }
}
core/.../models/impl/PageNavigatorImpl.java (key parts) Java 
@Model(adaptables = {SlingHttpServletRequest.class},
       adapters   = {PageNavigator.class},
       resourceType = {"wknd/components/login/page-navigator"},
       defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL)
public class PageNavigatorImpl implements PageNavigator {

    @Self  private SlingHttpServletRequest request;
    @OSGiService private ModelFactory modelFactory;
    @ChildResource private List<Resource> navItems;   // multifield

    @PostConstruct
    private void init() {
        // delegate illustration to Core Image
        modelFactory.getModelFromWrappedRequest(request, request.getResource(), Image.class);

        navItemList = navItems != null
            ? navItems.stream().map(NavItemImpl::new).collect(Collectors.toList())
            : Collections.emptyList();
    }
}

deploy issue Template not visible in page creation wizard
Root cause 1: missing initial + policies sub-nodes

AEM editable templates require three mandatory sub-nodes: structure, initial, and policies. Without initial and policies, the template engine considers the template incomplete and hides it from the wizard.

Root cause 2: cq:allowedTemplates did not include login-page-template

The property cq:allowedTemplates on /content/wknd/jcr:content lists which templates can be used to create child pages. The login template was missing from both ui.content and ui.content.sample.

fix Create initial + policies nodes; add template to cq:allowedTemplates in both modules
ui.content + ui.content.sample — /content/wknd/.content.xml
cq:allowedTemplates="[...,/conf/wknd/.../adventure-page-template]"
cq:allowedTemplates="[...,/conf/wknd/.../adventure-page-template,/conf/wknd/.../login-page-template]"

deploy issue Package changes not applied — Sling JCR Installer skips same version
Root cause: Sling JCR Installer skips reinstall of packages with same version

The all package deploys sub-packages to /apps/wknd-packages/content/install/. The Sling JCR Installer detects that 4.2.0 is already installed and skips it — even if the package content has changed. The fix is a manual Reinstall via AEM Package Manager after each build that modifies content packages.

http://localhost:4502/crx/packmgr/index.jsp → aem-guides-wknd.ui.content.sample-4.2.0 → Reinstall

deploy issue ui.content.sample deletes login-page-template on every install
Root cause: filter.xml uses replace mode for /conf/wknd/settings/wcm

ui.content.sample/filter.xml has <filter root="/conf/wknd/settings/wcm" /> — no mode attribute means replace. On install, AEM deletes everything under this path and reimports only what is in the package. Since login-page-template was not in ui.content.sample, it was deleted on every reinstall.

Fix: copy all login-page-template files into ui.content.sample/ conf/wknd/settings/wcm/templates/login-page-template/ (4 files)

deploy issue Created page has no CSS — clientlib not bound to template
Root cause: policies/jcr:content missing cq:policy for page clientlib

In AEM editable templates, the policies/jcr:content node must reference a page policy via cq:policy. That policy defines which clientlib categories (wknd.site, wknd.base, wknd.dependencies) are loaded for pages using this template. Without it, AEM renders the page with no stylesheets.

fix Add cq:policy reference to policies/jcr:content in both modules
login-page-template/policies/.content.xml — jcr:content
cq:policy="wknd/components/page/policy_1570140199406"
jcr:primaryType="nt:unstructured"
sling:resourceType="wcm/core/components/policies/mappings"

Policy policy_1570140199406 (WKND Site Theme) loads: clientlibs=[wknd.site, wknd.base], clientlibsJsHead=wknd.dependencies.
